Top risks:

1. **The committed leaderboard cannot be reproduced from the committed code** (AUD-01-P0): the pipeline writes each dataset's species from the model card, so regenerating from a fresh pipeline run corrupts the animal/plant/microbe arena split that the entire leaderboard navigation depends on. The committed data files (species `Animals`/`Plants`/`Microbe`) demonstrably predate the committed pipeline code.
2. **Batch benchmark runs train models under leaked configurations** (AUD-02-P0): after the first special-head or fp32-only model in `models_info` order, every subsequent model in the same process inherits the wrong head config and/or disabled mixed precision — published numbers would be produced under inconsistent benchmark conditions.
3. **Three of five production pages are dead or degraded** (AUD-09-P1 through AUD-12-P1): finetuning, models and datasets pages crash on load; the main leaderboard's sort controls do not work; four consumers misread the performance-JSON nesting.
4. **Derived data is not byte-reproducible** (AUD-08-P1): generator nondeterminism (unsorted directory iteration, unsorted JSON keys, live-clock date stamp) — already scheduled for in-phase repair (FIX-05, plan 01-03).

Positive verification result: the aggregation math itself (rank, MinMax, z-score, robust) was independently recomputed from the 42 raw model files and reproduces the committed `models_comparison.json` exactly (42/42 `rank_score` values within 1e-9) — the ranking engine is correct; the risks sit in the producers and the consumers.

## Severity definitions

- **P0 — leaderboard integrity:** anything that makes a published number wrong, risks data corruption, or exposes an unintended live secret. Aggregation math errors, pipeline data-integrity regressions, silent model dropping from rankings.
- **P1 — user-facing breakage or reproducibility:** dead pages, broken flows, nondeterminism, unreproducible environment, missing license — anything that breaks external trust or blocks the release.
- **P2 — hygiene and debt:** dead code, doc drift, console or log noise, performance — recorded and routed to the milestone backlog per D-03.

Grading rule: a finding is severity-graded only after independent reproduction (D-01). Candidates that could not be reproduced are listed under Unverified observations without a grade. Maintainability observations are recorded in the separate non-graded list (D-04) and never receive P0/P1/P2 grades.

## Methodology and limitations

**What ran.** Three subsystem reviews (pipeline, data scripts, frontend) with per-subsystem reproduction standards:

| Subsystem | Reproduction standard | Tools |
|-----------|----------------------|------|
| pipeline | Static code-path traces with quoted lines; data-side cross-checks against committed JSONs; module not importable (NameError — globals under the main guard) | Read, grep, jq over 42 model files + models_info + datasets_info |
| data | Runnable: scratch regeneration of the full chain (pinned env, plan 01-01 pin validation) plus an independent from-scratch recompute of the aggregation math in this audit | venv (pandas 2.3.3 / numpy 2.5.3), jq, baseline/compare.py |
| frontend | Browser rendering over a local static server (headless chromium DOM dumps + console logs); static grep traces where interaction-dependent; syntax via node --check | python3 -m http.server, chromium headless shell, node --check |

- **Pipeline** — static code-path traces with quoted lines (the module cannot be imported: its globals live under the `if __name__ == "__main__":` guard and `main()` raises NameError when imported), plus data-side cross-checks with jq over the 42 committed `model_performance` files, `pipeline/models_info.json` and `pipeline/datasets_info.json`. No GPU and no dnallm environment exists this phase; no pipeline code was executed.
- **Data scripts** — runnable reproduction: the full three-script chain was regenerated in a scratch mirror with the pinned environment (pandas 2.3.3 / numpy 2.5.3, CPython 3.13.16) during plan 01-01 pin validation (see `baseline/PIN-VALIDATION.md`); additionally the aggregation math (competition rank with method='min', N minus rank, guarded MinMax/z-score/robust, missing-metric exclusion) was independently recomputed from the 42 raw model files in this audit and reproduces the committed `models_comparison.json` exactly (42/42 rank_score values within 1e-9, zero unmatched models).
- **Frontend** — pages served over `python3 -m http.server 8080` and rendered in a headless chromium (Playwright-cached build); DOM dumps and console logs captured per page; `node --check` passed on all nine JS modules (all defects are runtime/logic, not syntax).

**Browser-verified frontend claims:** the three dead pages (finetuning, models, datasets — empty content containers plus the quoted TypeError per page), the working index page (42 model rows rendered), the working task page (47-task dropdown, 42-model default view), the BEND metric-dropdown selection defect (AUD-20), and the misleading Updated date (AUD-22).

**Static-verified-only frontend claims** (headless DOM dumps cannot exercise interactions): the sort-state application defect (AUD-11), the listener-loss class (AUD-12), the nesting misreads (AUD-10 — additionally masked on two pages by the AUD-09 crash), the XSS surface (AUD-14), the debug-API defect (AUD-21), and the stale-cache class (AUD-23).

**What did not run:** the fine-tuning pipeline (no GPU, no dnallm installation — every pipeline finding is a static trace with data-side cross-checks); no interactive browser session (no click-through); no network access beyond the local server.

**Scope equivalence:** the working tree equals the `data-v1` tag for all three audited subsystems (`git diff data-v1 -- pipeline/ script/ scripts/ dnallm-mark/` is empty); plan 01-01 added only root-level substrate files.

**Secrets:** the intentional Zenodo dataset-sharing link at README.md:116 is a recorded maintainer decision (kept as-is; record-scoped, read-only) and is excluded from findings by design. ### Expected post-fix migration inventory (pre-documented for plan 01-03)

The FIX-05 determinism fix in plan 01-03 intentionally changes derived-file bytes once. Against the `data-v1` baseline (see `baseline/PIN-VALIDATION.md`), the complete expected value-diff inventory is:

1. **Key-order changes** in all regenerated files — comparator-invisible (order-insensitive comparison unchanged).
2. **`sum_zscore` float noise** from the summation-order change: relative differences at or under 1e-12 tolerance (observed maximum 2.41e-14, on the order of 38-41 models per comparison file). All other fields (raw, MinMax, robust, rank_score, top-K counts, FLOPs, samples) are bit-identical.
3. **Rank swaps limited to exact-tie pairs** whose order is currently decided by filesystem iteration order: Omni-DNA-700M vs plant-dnabert-6mer (rank_score 1232.0, global file, ranks 13 and 14), gena-lm-bigbird-base-t2t vs hyenadna-large-1m-seqlen-hf (749.0, global file, ranks 29 and 30), and agro-nucleotide-transformer-1b vs plant-dnamamba2-BPE (448.0, microbe file, ranks 2 and 3 — an investigated addition to the two pre-documented pairs; same stable-sort root cause, documented in `baseline/PIN-VALIDATION.md`).
