<objective>
Add custom model/dataset storage-directory support to the benchmark platform so models and datasets can live outside the tiny system disk (e.g. under /root/autodl-tmp) while registry-relative `Model_path`/`Dataset_path` resolution stays byte-identical when no override is given.

Purpose: today every run_finetune subprocess runs with CWD pinned to `pipeline/` (run_sweep.py `cwd=PIPELINE_DIR`), so registry values like "models/Chaoba" and "datasets/BEND/..." always resolve against `<repo>/pipeline/` with no override entry point; the TUI's RunSpec.dataset_root is display/docs-only (D-19) and there is no model-root field at all. This plan lands `--model_root`/`--dataset_root` across run_finetune + run_sweep (pass-through, cache_dir-style), threads dataset_root live from the TUI service, and adds the model_root TUI field end-to-end.

Output: two pipeline flags with tests, a live-threaded TUI service spec, a new screen input row with strings + regenerated golden.

Decisions reconciled from the task description (recorded so the executor does not re-litigate):
- Flag spelling is UNDERSCORE everywhere (`--model_root`, `--dataset_root`) in run_finetune, run_sweep, and the TUI-composed argv. The description's item 2 hyphen spelling ("--dataset-root") is a slip: item 1 defines the flags with underscores, the flags join the `--subset_file`/`--cache_dir` underscore pass-through family, and a hyphen token would be rejected by run_sweep's argparse outright.
- Flag semantics: the flag value is the ROOT under which the registry-relative path resolves VERBATIM (replacing the `pipeline/` script-dir root). `--model_root /root/autodl-tmp` + Model_path "models/Chaoba" resolves to /root/autodl-tmp/models/Chaoba. No prefix stripping, no registry-shape magic (custom-registry entries store pipeline-relative paths the same way — tui/services/custom_entries.py lands them via `os.path.relpath(raw_path, PIPELINE_DIR)`).
</objective>
