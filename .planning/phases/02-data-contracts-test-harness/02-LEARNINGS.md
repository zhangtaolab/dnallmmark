# Phase 2 Learnings: Data Contracts & Test Harness

## Decisions

### All-strict schemas with closed enums and a data≡enum self-check
All four JSON Schemas are `additionalProperties: false` with every field required; metric/species/type fields use closed enums extracted from the 50 committed datasets; a unit test asserts each enum equals the set of values actually present in committed data, so enum and data cannot silently diverge.

**Rationale:** Maintainer's consistent maximum-strictness preference (chosen above the recommended looser options twice in discuss-phase); forced versioning is reviewer-friendly; typos fail immediately.
**Source:** 02-CONTEXT.md (D-01/D-02), 02-01-SUMMARY.md

### xfail(strict=True) with finding-ID reasons is the house style for known defects
Defect semantics are locked as failing tests (species-as-dataset AUD-01-P0, comparator bool/int WR-02, non-finite poisoning WR-03); `strict=True` makes an unexpected XPASS fail the suite, forcing the Phase 4 fixer to remove markers deliberately in the fix commit.

**Rationale:** A fix can never land silently; the test file is the fix audit trail.
**Source:** 02-CONTEXT.md (D-03/D-04), 02-03-SUMMARY.md

### Goldens are chain-produced, never hand-authored
The synthetic golden files were generated by actually running the three-script chain over the fixture tree in a scratch run and committing the outputs; hand-authoring expected outputs was rejected.

**Rationale:** A hand-written expected output encodes the author's belief, not the generator's behavior.
**Source:** 02-02-SUMMARY.md

### Self-contained schemas (duplicated enums) over cross-file $ref
The four schema files duplicate their shared enums rather than referencing a common $defs file; the widening self-check test (IN-02 fix) covers the duplication risk instead.

**Rationale:** RESEARCH open question 1 resolved to duplication-first — cross-file $ref + Registry is a consolidation option later, not a day-one dependency.
**Source:** 02-RESEARCH.md (Open Questions RESOLVED), 02-01-PLAN.md

### make lint scoped to tests/ only this phase
`make lint` runs ruff over tests/ alone, with the scoping reason documented in the Makefile comment: script/, scripts/, baseline/, pipeline/ carry ~21 pre-existing findings and D-04 forbids production changes.

**Rationale:** Widening scope silently would either fail on pre-existing debt or tempt drive-by fixes outside phase discipline.
**Source:** 02-01-SUMMARY.md, Makefile

### Advisory-findings routing by destination phase
Review findings route to the phase that touches their code: IN-01/IN-03 deferred to Phase 4/5 under the D-04 production-change prohibition (rationale recorded in REVIEW-FIX.md), rather than fixed opportunistically.

**Rationale:** Phase discipline ("build contracts, change no production code") outweighs the temptation of small drive-by fixes.
**Source:** 02-CONTEXT.md (D-05), 02-REVIEW-FIX.md, 02-REVIEW-DISPOSITION.md

### Measured wall time replaces planning folklore in docstrings
The determinism test's docstring records the measured ~0.3s per chain run, replacing D-10's never-re-timed ~40s figure; the `slow` marker stays for lane-quality reasons, documented as such.

**Rationale:** A wrong number in a docstring propagates; measured reality is cheap to record.
**Source:** 02-03-SUMMARY.md

## Lessons

### pytest.fail inside xfail(strict=True) is still reported as XFAIL
The AUD-01 lock's "honesty guard" (`pytest.fail` on anchor loss) was swallowed by its own marker — empirically confirmed on pytest 9.1.1. An xfail-wrapped test cannot loudly report anything.

**Context:** WR-01 of the phase review; fixed by an UNMARKED companion test asserting the anchor is findable and unique (later narrowed by IN-05 to also assert the "species" key remains at the site).
**Source:** 02-REVIEW.md (fix-round delta), 02-REVIEW-FIX.md (WR-01, IN-05)

### `default-groups` in pyproject REPLACES uv's default, it does not extend it
With `default-groups = ["data"]`, a bare `uv run pytest` fails — the dev group is not included. Every Makefile target must pass `--group dev` explicitly.

**Context:** Research pitfall 2, verified live; every Makefile recipe line carries the flag with an explanatory comment.
**Source:** 02-RESEARCH.md (Pitfalls), Makefile

### A single missing dependency spans multiple surfaces — guard them all
The node dependency touches three surfaces (JS test lane, golden tests' generator step, `make data`); the first fix guarded only the test target and its escape-hatch message was factually wrong (test-fast still ran node-dependent golden tests). Convergence required: `data: check-node`, module-level skipif on test_golden, and a truthful message.

**Context:** IN-04 → fix round 1 → WR-06/WR-07 → fix round 2 → clean.
**Source:** 02-REVIEW.md (delta), 02-REVIEW-FIX.md (round 2)

### Plan arithmetic errors surface at execution time and executors catch them
Two plan-text errors (a constant-score expectation wrong by one ULP; a rank-total arithmetic slip) and one research path anchor resolving outside the repo (`parents[2]` vs `parents[1]`) were all caught by executor Rule-1 auto-fix with documentation.

**Context:** Deviations sections of all three SUMMARYs. Lesson: floating-point expectations in plans need binary-exact values or approx semantics, not decimal folklore.
**Source:** 02-02-SUMMARY.md (Deviations 1-2), 02-03-SUMMARY.md (Deviation 1)

### Disposition reconciliation is title-sensitive — re-titled fix entries do not auto-match
The ledger's fix-report reconciliation matches finding ID AND title; fixer-authored REVIEW-FIX headings that paraphrase the review's titles do not reconcile, leaving genuinely-fixed rows recorded as open. Required hand-reconciliation in both fix rounds (and the same tool's id-reuse edge bit Phase 1).

**Context:** 02-REVIEW-DISPOSITION.md reconcile runs; the tool reports the un-reconciled IDs by name, which makes the hand-fix auditable.
**Source:** 02-REVIEW-DISPOSITION.md

### Dispatch-isolation sentinels are exact-string matched — zero-padding matters
The Agent isolation guard compares sentinel phase/plan identifiers as strings: `--phase 2` did not apply to a dispatch carrying `phase="02"`. Record sentinels with the padded form used in dispatch prompts.

**Context:** Wave-1 dispatch was blocked twice before the padded sentinel (`--phase 02`) applied.
**Source:** .gsd/dispatch-isolation-sentinel.json (session 2026-10-09; orchestrator record)

### Verifier reports must carry a `status:` key at column 0
One reviewer omitted the frontmatter `status` key, breaking the disposition step's parser (and one orchestrator-side check with a missing multiline flag mis-diagnosed the inverse). Agent-authored report frontmatter needs format validation before downstream consumption.

**Context:** 02-REVIEW.md frontmatter repair (commit 61308cc).
**Source:** 02-REVIEW.md

### The fingerprint contract punishes hallucinated paths — verify the report's own list against disk
Two verifier runs project-wide wrote covered_files entries that do not exist (a display pseudo-entry; a spliced filename). The discipline that works: run the fingerprint CLI over the intended list (it fails closed on any missing path), then verify the report's written list matches disk exactly.

**Context:** Phase 1 and Phase 2 verification runs; the final Phase 2 run honored it (31 files verified on disk).
**Source:** 01-VERIFICATION.md, 02-VERIFICATION.md

## Patterns

### Fix-round convergence loop (review → fix → delta-review → … until clean)
After execution, the review-fix cycle iterates with ever-narrowing delta scopes (full phase → fix-round files → fix-round-2 files) until a delta review returns clean. Findings shrank 9 → 3 → 0. Each fix is atomic, contrast-verified (pre-fix stash vs post-fix behavior), and the disposition ledger is reconciled after each round.

**When to use:** Any phase where review findings warrant code changes; bound it by convergence (clean delta) rather than a fixed count.
**Source:** 02-REVIEW.md, 02-REVIEW-FIX.md (rounds 1-2), 02-REVIEW-DISPOSITION.md

### --runxfail false-lock probe
`pytest tests/test_known_defects.py --runxfail` must FAIL on the real defect assertions (not import/collection errors) — proving each xfail lock locks the actual defect rather than an environment artifact.

**When to use:** Whenever xfail markers encode known defects; pair with unmarked companion tests for anchor integrity.
**Source:** 02-03-SUMMARY.md, 02-VERIFICATION.md

### Unmarked companion test guarding an xfail anchor
An unmarked test asserts the anchor the xfail lock depends on (findable, unique, still containing the key field) so anchor drift fails LOUDLY outside the marker's swallow.

**When to use:** Any AST/source-contract xfail whose lock can silently vacate if the anchored code moves.
**Source:** 02-REVIEW-FIX.md (WR-01, IN-05)

### Bucket-count canary against vacuous green
A canary test pins the exact expected file counts per glob bucket (42/47/4/1) so a missing or partial data tree fails loudly instead of yielding zero collected items and a green suite.

**When to use:** Any parametrized-over-glob test suite where an empty glob is a bug, not a pass.
**Source:** 02-REVIEW-FIX.md (WR-03)

### Copy-into-fixture-tree for import-time-executing scripts
The CommonJS index generator executes on import and resolves paths via __dirname, so CWD cannot redirect it; copying the script into a tmp fixture tree (mkdtemp) confines its execution and output without touching the repo.

**When to use:** Testing file-system scripts with import-time side effects and no CLI entry point.
**Source:** 02-RESEARCH.md (Patterns), 02-02-SUMMARY.md

### Contrast verification (pre-fix stash vs post-fix)
Every fix demonstrates the failure it claims to fix: reproduce the broken behavior with the pre-fix code (git stash), show the fixed code passes, and record both observations in the fix report.

**When to use:** Fix rounds; the evidence makes REVIEW-FIX self-auditing and caught two fixes that would otherwise have claimed more than they delivered (WR-06's message, the vacuous guard).
**Source:** 02-REVIEW-FIX.md (rounds 1-2)

## Surprises

### The determinism chain runs in ~0.3s, not ~40-80s
D-10's ~40s/chain estimate (and the plan's ~80s) were never-measured planning figures; the real tree (42 models, 47+4+1 outputs) regenerates in a third of a second warm.

**Impact:** The `slow` lane is qualitative, not quantitative; CI (Phase 5) can afford to run the determinism test on every push.
**Source:** 02-03-SUMMARY.md

### Executor token actuals came in at ~36% of estimate
02-01 measured ~16.3K tokens against a 45K estimate; the estimate-calibration factor stays at 1 with sample_count below the 3-phase threshold.

**Impact:** Phase 3 estimates should not be mechanically inflated; calibration will start feeding back after Phase 3.
**Source:** 02-01-SUMMARY.md (actuals)

### The first node-guard fix was itself the source of two new warnings
A one-line guard (`check-node`) introduced WR-06 (false escape-hatch message + unguarded fast lane) and WR-07 (unguarded `make data`) — the delta review caught both.

**Impact:** Confirms the value of reviewing fix rounds rather than trusting green suites; small "obvious" fixes carry their own failure surface.
**Source:** 02-REVIEW.md (delta round)

### pytest 9 rejects unused parametrize argnames at collection
Discovered during research probes; a parametrized test with an unused argname is a collection error, not a warning.

**Impact:** Fixture/parametrize discipline in test authoring; documented in research and honored in the shipped tests.
**Source:** 02-RESEARCH.md (Pitfalls)

### Hostile-environment behavior flipped from defect to feature via force-assign
Pre-fix, `OMP_NUM_THREADS=4` in the environment turned the suite red with a bare AssertionError (WR-05); post-fix (conftest force-assign before numpy import), the same hostile env runs fully green — the pinning now wins instead of merely detecting.

**Impact:** "Stable by construction" now includes hostile-environment override, verified as one of the acceptance probes.
**Source:** 02-REVIEW-FIX.md (WR-05), 02-VERIFICATION.md
