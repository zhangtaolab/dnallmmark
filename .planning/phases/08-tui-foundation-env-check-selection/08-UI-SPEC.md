# Phase 8 — UI Design Contract

> Visual and interaction contract for the DNALLM-Mark terminal console (Textual TUI).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **TUI adaptation note.** This is a terminal application, not a web UI. The web
> leaderboard's CSS custom properties (`dnallm-mark/css/variables.css`) are NOT the design
> system here; they inform only the accent hue (teal family) for brand continuity. Design
> tokens are Textual theme variables expressed in `tui/styles.tcss`. px-based dimensions
> (spacing in px, font sizes) do not exist in a terminal — their contract equivalents are
> declared below in **terminal cells** (1 cell ≈ 8–9 px wide × 16–21 px tall at typical font
> sizes), and typographic hierarchy is expressed through **weight + color + position**, the
> only axes a monospace grid offers. Phase mode is `--auto`: every design question that
> would have been asked is recorded in `## Auto-Selected Defaults` as a recommendation the
> maintainer may override at plan review.

## Terminal Contract

The runtime surface this design must survive (binding context: SSH/tmux on GB10; success
criterion 1; 08-RESEARCH Environment Availability):

| Property | Value |
|----------|-------|
| Minimum grid | 80×24 — below this, render a centered polite message `终端过小（需 ≥ 80x24，当前 {w}x{h}）— 请放大窗口` and nothing else (tui-design stability rule; re-check on resize) |
| Design grid | 120×40 (matches the Pilot test size in 08-RESEARCH Pattern 7) |
| Encoding | UTF-8 required (CJK copy + glyph vocabulary); tmux 3.4 verified on the operator path |
| Color depth | design against Textual theme tokens which degrade truecolor → 256 → 16 → `NO_COLOR` automatically; **bold/reverse/glyph redundancy must survive `NO_COLOR`** (glyph+color rule below) |
| Mouse | additive only — every action keyboard-reachable (keyboard-first, k9s mental model) |
| Wide chars | CJK = 2 cells; all measurement is Textual/Rich display-width (never `len()`) — repo has zero hand-rolled width math to write |
| Quit safety | terminal state restored on every exit path (Textual default; do not disable) |

## Screen Layouts

Three screens, no sidebar (terminal width is precious at 80 cols; navigation is key-driven
and discoverable via Footer). App opens on the env-check screen; screens switch by key, not
tabs — rationale in Auto-Selected Defaults #4.

### Screen 1 — 环境检查 (startup default; ENV-01..04)

```text
 DNALLM-Mark 控制台 — 环境检查                 上次检查: 2026-10-11 16:20
 ────────────────────────────────────────────────────────────────────────
  状态   检查项           摘要
  ✓      版本 pin         torch 2.11.0 == pyproject [gpu] pin
  ✓      dnallm 导入      import dnallm resolves
  ⠋      peft             检查中…
  ◌      cuda             待检
  ◌      matmul           待检
  ✓      numpy≥2          numpy 2.5.3 >= pyproject floor
  ✗      数据集目录       7 of 50 registry dataset dir(s) missing
 ────────────────────────────────────────────────────────────────────────
  ✗ 关键项未通过: cuda — 启动流程将被阻断（阻断接线于 Phase 11）
  ⚠ 7 个数据集目录缺失 — 数据下载面板于 Phase 10 提供；CLI 重跑审计可刷新
 ────────────────────────────────────────────────────────────────────────
  [r] 重检  [enter] 详情  [s] 选择  [?] 帮助  [q] 退出
```

- Row order = `main()` kernel order (version_pins, dnallm, peft, cuda, matmul, numpy,
  dataset_dirs — 08-RESEARCH verified); row order is part of the contract.
- Async fill: every row starts `◌ 待检` (dim); each kernel completion posted from the
  `@work(thread=True)` worker flips its row to `✓`/`✗` inline (inline loading, never a
  full-screen spinner — cached same-day results render instantly, D-03/D-05).
- The two-line verdict/routing block at the bottom is the ENV-03 surface (copy in
  Copywriting Contract); it is advisory in Phase 8 — D-09 wires actual blocking in Phase 11.

## Spacing Scale

Declared values in **terminal cells** (the terminal has no px; 1 cell ≈ 8–9×16–21 px —
multiples of 4 cells are the rhythm, ≈32 px steps):

| Token | Value | Usage |
|-------|-------|-------|
| md | 4 cells | Default padding inside panels/modals (`padding: 1 4`), table-to-filter separation |
| lg | 8 cells | Vertical separation between major regions (title / table / verdict blocks) |
| xl | 12 cells | Screen-edge margin on terminals ≥ 120 cols only |
| row | 1 cell (height: 1) | DataTable data rows — one line per row, no extra cell padding |
| modal | width 60 cells, `padding: 1 4` | Modal dialogs (min(60, width−4) at narrow sizes) |

Exceptions: **1-cell** widget borders and `padding: 0 1/0 2` on filter input, footer, and
status lines (terminal-intrinsic; Textual default chrome), and **2-cell** compact gutters
between the filter bar and the table. These are exceptions, not tokens — do not invent
intermediate values (no 3-, 5-, 6-cell paddings anywhere).

## Typography

One glyph size exists in a terminal; hierarchy is weight + color + position. Exactly **2
weights**, 4 roles:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (table cells, detail lines, copy) | 1 cell (terminal default) | regular | 1.0 (1 cell/line) |
| Secondary (hints, placeholders, 待检 rows, muted columns) | 1 cell | regular + `$text-muted` (dim) | 1.0 |
| Heading (screen titles, table headers, modal titles) | 1 cell | **bold** (`text-style: bold`) | 1.0 |
| Emphasis (marked ✓, counts, key values, verdict glyphs) | 1 cell | **bold** | 1.0 |

- Table header row: bold + `$text-muted` on `$surface` (DataTable `datatable--header`).
- CJK copy counts double width: keep Footer binding labels ≤ 4 CJK chars (标记/预设/矩阵/
  模板/重检/详情), section titles ≤ 8; all width math is Rich's (never hand-padded).
- No italics, no underline, no blink anywhere; reverse-video is reserved for cursor focus
  (Textual DataTable default) and is never used as a data signal.

## Color

Semantic Textual theme tokens are the contract — they adapt to light/dark/`NO_COLOR`
automatically. Hardcoded hex is **forbidden in screens/widgets and in `styles.tcss`**; the
only permitted hex is inside a single optional custom theme definition (see below).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `$background` | app background, DataTable body, matrix base |
| Secondary (30%) | `$surface` / `$panel` / `$boost` | Header/Footer, filter bar, table headers, zebra stripes, verdict block backing, modal surfaces |
| Accent (10%) | `$accent` | reserved list below |
| Success | `$success` | presence ✓, env PASS ✓, 可启动 verdict |
| Warning | `$warning` | 缺数据 routing banner, unknown-preset-key warnings |
| Destructive | `$error` | presence ✗, env FAIL ✗, critical-fail banner, destructive confirm borders, template-validation error text |

**Accent reserved for** (exhaustive — never "all interactive elements"):

1. the 标记 column `✓` glyph (bold) and the `◆` mark prefixes in the matrix view
2. the focused filter Input border/caret
3. Footer keycap hints (the key char only — descriptions stay `$text-muted`)
4. the active screen name in the Header sub-title
5. matched-substring highlighting inside filtered table rows
6. the preset-applied / template-exported toast accent

**Glyph+color redundancy rule (SSH/tmux):** every color-coded state carries a distinct
glyph first — `✓` pass/present, `✗` fail/missing, `⚠` routing/warning, `◌`/`⠋` pending,
`◆` marked. The UI must remain fully legible under `NO_COLOR` / `TERM=dumb` (glyph + bold
carry the meaning; this is testable and part of the Pilot assertions).

**Brand continuity (optional, single-site hex):** a custom theme `dnallmmark` may map
`$accent` to the leaderboard teal family — `#568788` on dark backgrounds, `#265354` on
light (from `dnallm-mark/css/variables.css` `--color-accent-teal-soft`/`--color-accent-teal`;
the mid `#3B7475` fails contrast on dark). All other tokens stay Textual defaults. If the
custom theme is skipped, default theme tokens satisfy this contract unchanged.

## Keyboard & Interaction Contract

k9s mental model: type-to-filter, spacebar-mark, keyboard-first. Footer always shows the
active screen's bindings (Chinese labels). `?` opens a help modal listing every binding.

| Key | Screen | Action |
|-----|--------|--------|
| `r` | 环境检查 | 重检 — force full re-run (exclusive worker; rows reset to ◌ then fill in kernel order) |
| `enter` | 环境检查 / 选择 / 矩阵 | drill-down modal (env detail lines verbatim / row card fields / full task key) |
| `s` | 环境检查 | switch to 选择 screen |
| `/` | 选择 | focus filter Input (placeholder `输入过滤词…`); `esc` clears filter + refocuses table |
| `space` | 选择 | toggle mark on cursor row of the **active** table only |
| `m` | 选择 | toggle 模型 ⇄ 数据集 table (mark sets preserved independently) |
| `p` | 选择 | open preset SelectionList modal (tier-1 E2E 对 / tier-2 arena 代表 / 全部 / 自定义保存…) |
| `s` | 选择 | save current mark sets as custom preset (name Input modal) |
| `x` | 选择 | template modal menu: 导入模板 / 导出模板 / 转 sweep_priorities tier |
| `v` | 选择 | push 矩阵总览 (read-only; no mark bindings there) |
| `esc` | modals / 矩阵 / filter | pop modal / clear filter — never quits the app |
| `q` | app | quit (terminal state restored) |
| `?` | app | help modal (all bindings, Chinese) |

(Both 环境检查→选择 and 选择→save-preset use `s` on different screens — allowed; bindings
are per-screen. If the executor finds a conflict in Textual's dispatch, `S` (shift) for
save-preset is the sanctioned fallback.)

**Interaction semantics that are contract, not implementation detail:**

1. **Mark-set** — marks live in app state keyed on the registry key (stable `RowKey`), never
   in the table; filter rebuilds (`clear()` + re-`add_row(key=…)`) and table switches cannot
   lose them. DataTable has no multi-select — the spacebar binding + 标记 column update via
   `update_cell` is the whole mechanism (08-RESEARCH Pattern 3 / Pitfall 1).
2. **Filter grammar** — space-separated AND terms; each term is either a bare substring
   (matched against key + displayed columns) or `axis=value`. Valid axes (registry-verified
   enums, 08-RESEARCH): models `species`, `type` (MLM/CLM/DL), `size`; datasets `category`
   (Animals/Plants/Microbe/Multiple), `type`, `metric`. Unknown axis/value → dim inline
   warning line under the Input, filter still applies for valid terms. Live row-count
   readout `(N/62)` right-aligned in the filter bar.
3. **Preset application** — replacing semantics (not additive): applies to the relevant
   mark set(s), updates the status line, and fires a toast (`✓ 已应用预设 …`). tier-1 marks
   its pair models **and** the pairs' tasks; tier-2 marks models only; 全部 marks every key
   of the overlay-merged registry in both lists; 自定义 restores both sets as saved.
   Preset keys not present in the current registry are skipped with a loud `⚠` warning
   listing them (registry evolution tolerance, 08-RESEARCH Pattern 5).
4. **Template import** — path Input modal → jsonschema validation with **collect-all**
   listing (never one error at a time) → on success marks are applied + toast; on failure a
   numbered problem list and nothing changes (D-07 fail-fast discipline).
5. **Env-check caching** — same-day (local calendar day) cached result renders instantly
   with the `上次检查:` line; `r` is the only path that re-runs kernels (D-05). Partial
   failures persist and render as FAIL rows on next startup.
6. **ENV-04 quick check** — service + strings only this phase; no UI surface (D-09 — the
   launch-flow call site is Phase 11).

## I18N Contract (I18N-01)

- **Single home:** `tui/strings.py` — plain module-level `UPPER_SNAKE` constants, grouped
  by screen prefix (`APP_`, `ENV_`, `SEL_`, `MATRIX_`), format fields as `{name}` consumed
  via `.format()` at render sites. No other module defines operator-facing copy (testable:
  grepping widgets/screens for Chinese literals outside `strings.py` should find none).
- **Language rule:** UI copy 中文为主; technical terms stay English verbatim — model/dataset
  registry keys, kernel ids, filter axes, metric names, file paths, CLI commands, schema
  field names. Never translate registry keys or argv.
- **Kernel detail lines are data, not copy** — drill-down shows the kernel's own English
  PASS/FAIL lines verbatim (they are the byte-stable env_smoke contract, D-02); Chinese
  chrome wraps them (title, footer).
- **No runtime locale switching** in Phase 8 — the constants module is the seam that would
  make it possible later; do not build a translation framework.
- Requirement-verbatim strings (`上次检查: YYYY-MM-DD HH:MM`, `✓ 在场 / ✗ 缺失`) land in
  `strings.py` exactly as specified above.
