# Phase 16 — UI Design Contract

> Visual and interaction contract for the three Phase-16 surfaces: the **G
> GPU-lanes panel** and **dispatch rows** on slot-5 (TUI-01/TUI-03), and the
> **slot-4 multi-GPU launch** (TUI-02), with **snapshot goldens** for changed
> screens (TUI-04). Generated by gsd-ui-researcher, to be verified by
> gsd-ui-checker.
>
> **Evolution contract.** This spec **inherits the approved Phase 11/12
> contracts** (11-UI-SPEC approved 2026-10-13; 12-UI-SPEC approved as the
> hardening layer), which inherit Phases 8–10. Inherited verbatim, by
> reference: the **Terminal Contract** (80×24 minimum + min-size guard,
> 120×40 design grid, UTF-8, NO_COLOR degradation, keyboard-first, wide-char
> discipline), the **Navigation Shell** (top menu + bottom submenu, digit nav
> 1–6, one navigation path per target), **Spacing** (cell tokens md 4 / lg 8
> / xl 12; modal `padding: 1 4`; modal tokens 60/100; row tokens height 1;
> status-line exceptions `0 1`/`0 2`), **Typography** (1 terminal size, 2
> weights — regular + bold), the **I18N Contract** (`tui/strings.py` single
> home, bilingual registry, zh terminology table, default English), the
> glyph+color redundancy rule and glyph vocabulary (✓ ⠋ ✗ ⊘ ◌ ⏵ ⏸ ◆ ⚠), the
> services-textual-free import lock, the worker-guard discipline, the rze
> render-gate law (a steady tick over unchanged data performs ZERO widget
> writes), and the bottom-bar clip policy. **16-CONTEXT D16-01..D16-15 are
> RATIFIED — this spec does not re-open them.** This phase adds **no glyph,
> no spacing token, no color value, no weight, no keybinding, and no new
> screen** — every surface is a section/row/modal-line on EXISTING screens
> (D16-05, D16-13), expressed only through existing `styles.tcss` tokens and
> new `strings.py` constants.
>
> **The existing TUI IS the design system.** `tui/styles.tcss` (semantic
> Textual theme tokens only — hardcoded hex forbidden) and `tui/strings.py`
> (bilingual registry) govern; this contract EXTENDS them, never parallels
> them. TUI orchestrates, never computes: every number rendered arrives from
> a service (gpu_probe rows, dispatch_state dataclasses, launcher facts) —
> the screens own only cadence, focus, and rendering.

## Overview & Information Architecture

Phase 16 closes the v1.3 operator loop: the console that validated
multi-GPU dispatch on the CLI (Phases 13–15) now launches and watches it
natively. Three surfaces, all on existing screens:

```text
 slot 4 运行配置 (run_config, EXISTING)
   params pane gains a 多 GPU 调度 section: workers / GPUs fields → RunSpec
   composer → run_sweep_shard.py --mode dispatch --workers N --gpus … (D16-09)
   gate chain UNCHANGED: [enter] → enumeration problems → multi-GPU-aware
   stage (replaces EHC-3 single-GPU refusal) → env preflight → confirm
   (dispatch-plan line + pairs) / E2' typed phrase (full scope) → launch
                     │ launch (detached, tee, registry — unchanged seams)
                     ▼
 slot 5 任务监控 (monitor, EXISTING)
   Running card gains dispatch rows: dispatch line (status · done/total ·
   queue) + one row per worker (in-flight cell or idle)   ← tui/services/
   dispatch_state.py reads the frozen v2 schema, stale-marked >60s (D16-08)
   G GPU-lanes panel: standing full-width section under the tab content,
   both tabs, one lane per GPU                          ← tui/services/
   gpu_probe.py (nvidia-smi CSV → frozen rows, 未安装 degradation, D16-01..04)
                     │
 snapshot goldens: run_config + monitor_empty + monitor_running regenerate
 (uncommitted, D-03); one NEW confirm-face golden (D16-13)
```

| Surface | Kind | Delivers |
|---------|------|----------|
| G GPU-lanes panel (slot-5) | NEW standing section on an EXISTING screen | per-GPU lane rows (index / utilization bar+% / memory used-total / temperature) on the 2s monitor cadence; honest 未安装 + N=0 empty states (TUI-01) |
| Dispatch rows (slot-5 Running tab) | NEW rows on the EXISTING running card | dispatch line (queue depth, status) + per-worker in-flight rows from `dispatch_state.json` v2, stale-marked (TUI-03) |
| Slot-4 multi-GPU launch | EXISTING params pane + EXISTING gate modals | workers/GPUs fields → dispatch argv; dispatch-plan preview line on the confirm face; single-GPU serial gate replaced by multi-GPU-aware semantics, chain order untouched (TUI-02) |
| Goldens | regenerated + 1 new SVG | changed screens only, uncommitted pending D-03 review (TUI-04) |

**Out of scope (locked):** any new screen or keybinding; DDP; cost
prediction; pynvml (rejected in REQUIREMENTS); web surfaces (Phase 17);
docs (Phase 18); G-panel configuration/pinning of GPU→cell assignment.

## Surface A — G GPU-Lanes Panel (slot-5, TUI-01)

A **standing full-width section** on the monitor screen: below the tab
content region, above the bottom bar, visible on **both tabs** (GPU state is
machine-level, not run-level — it never disappears when the operator flips
to History). The Running/History tab structure is untouched (D16-05).

### Layout contract

```text
#mon-screen (120×40 design grid; works at 80×24 minimum)
┌────────────────────────────────────────────────────────────────────┐
│ 任务监控                         扫描: 前沿 2s · 全扫 60s            │  ← unchanged
│ 正在运行 (1)  历史 (3)                                              │  ← unchanged
│ ┌ #mon-content (B+D split — unchanged) ─────────────────────────┐ │
│ │ … running card (Surface B rows live here) / History table …   │ │
│ └───────────────────────────────────────────────────────────────┘ │
│ ── #mon-gpu (NEW: border-top separator, the #dl-queue-region     │
│    precedent) ──────────────────────────────────────────────────  │
│ GPU 状态                                      ◌ nvidia-smi 未安装  │  ← header row + probe state
│ GPU 0 [██████████░░░░░░░░░░]  47%   15340/32607 MiB  61°C         │  ← one lane row per GPU
│ GPU 1 [███░░░░░░░░░░░░░░░░░]  12%     958/32607 MiB  33°C         │
│ [bottom-bar keycaps — unchanged]                                   │
└────────────────────────────────────────────────────────────────────┘
```

**Rules (prescriptive):**

1. **Position & chrome**: `#mon-gpu` is yielded between `#mon-content` and
   `BottomBar()` in `MonitorScreen.compose`. Chrome = `border-top: solid
   $border` (the full-width separator family; borders stay reserved for
   modals/panes elsewhere), header row + N lane rows. New TCSS follows the
   file's documented pattern verbatim: row tokens (`height: 1`), the
   2-cell status-line padding exception (`padding: 0 2`), theme tokens
   only, one comment block naming this phase.
2. **Header row**: left = `MON_GPU_TITLE`; right (1fr, right-aligned,
   `$text-muted`) = the probe-state note — normally the last-probe say-
   nothing (blank; healthy data needs no narration), the `MON_GPU_ABSENT`
   copy when degraded. The probe state never occupies its own row (the
   80×24 budget owns it).
3. **Lane row format** (data-forward; `MON_GPU_ROW` + the code-composed
   bar): `GPU {i}  [{bar}]  {util}%  {used}/{total} MiB  {temp}°C` —
   ~44 cells at the widest (6-digit MiB), safe at 80 columns. Bar = 10
   cells, the existing segmented-bar grammar: filled = the cyan running
   channel, empty = the dim `░` queued channel (activity semantics, no new
   color meaning). Numbers render default `$text`; no per-threshold
   recoloring of utilization/temperature this phase (a fabricated
   warning threshold is a number the probe never provided).
4. **Sort & count**: rows sorted by index ascending (D16-04); N rows for
   N GPUs (the validation machine renders 2).
5. **Empty / degraded states** (all glyph-first, NO_COLOR-legible):
   - **Binary absent OR non-zero exit OR probe exception/timeout** → the
     header note renders `MON_GPU_ABSENT`; the lane region renders ZERO
     rows (never fabricated lanes, never a crash — D16-02). One shape for
     every failure mode (the deps-tolerance 未安装 precedent).
   - **Probe succeeds with N=0 rows** → one lane-region row
     `MON_GPU_NONE` (the explicit empty state, D16-04).
   - **First paint** (before the first probe message lands): header row
     only, note blank, zero lane rows — the #41 optimistic-paint law
     (skeleton + nothing; never a guessed lane).
6. **Cadence & worker discipline** (D16-03): the 2s frontier timer
   dispatches ONE exclusive `@work(thread=True, group="mon-gpu")` probe;
   the subprocess call carries a ~2s timeout so the UI never blocks; no
   resident poller thread. The gpu_probe service itself is a pure
   callable (no timers — the scanner's declaration); the screen owns
   cadence, as everywhere.
7. **Render-gate membership (the rze law)**: every G-panel widget is
   content-signature gated — a steady 2s tick over unchanged rows writes
   zero; the signature covers (probe-state, row count, per-row values);
   `on_mount` resets the sentinel so the L-toggle recompose repaints
   (the existing idempotent-remount contract). Suppressed while a modal
   is stacked (the `_render_all` early-return).
8. **Focus**: `#mon-gpu` is display-only (`can_focus = False` on the
   container — the `#mon-right-log` precedent); every key stays
   screen-level. **No keybinding is added** — no `[g]` toggle; the panel
   is standing chrome like the scan note.
9. **Overflow bound**: many GPUs (8-way boxes) — the lane region carries
   `height: auto; max-height: 8` (a SCROLL BOUND, not a spacing token —
   the `#env-detail-log` precedent); rows scroll their own viewport.
   Cost at the 80×24 floor on the 2-GPU validation machine: 3 rows
   (header + 2 lanes), documented and accepted; the card list above
   scrolls.
10. **Both languages**: values are data compositions; the zh side keeps
    `%`, `MiB`, `°C`, `GPU`, `nvidia-smi` verbatim (the MON_COL_SEED /
    MON_STRIP_RATE data-forward precedent).

## Surface B — Dispatch Rows (slot-5 Running tab, TUI-03)

The running card (the B skeleton: summary strip → matrix/tree/wide) gains
a **dispatch block**, rendered ONLY for roots carrying
`{root}/dispatch_state.json` (mode evidence). Static/CLI sweep roots and
`-mgpu-w*` worker roots render exactly as today — zero regression surface.

### Layout contract

```text
 running card (inside #mon-cards, one per live run)
 ┌──────────────────────────────────────────────────────────────────┐
 │ {root} · ⏵1 ✓9 ✗1 ⊘1 ◌20 [████░░░░…] 12/32  耗时 45m  预计 …     │  ← strip, unchanged
 │ 调度 running · 完成 9/32 · 队列 20                                │  ← MON_DISPATCH_LINE (NEW)
 │ worker 0 · GPU 0 · ⏵ plant-dnabert-6mer × 5mC × seed_42          │  ← busy row (NEW)
 │ worker 1 · GPU 1 · ◌ 空闲                                        │  ← idle row (NEW)
 │ ⚠ 调度状态过期（{age}s ≥ 60s）— 数据可能不是最新                    │  ← stale row (NEW, only when stale)
 │ [matrix / tree / wide — unchanged]                                │
 └──────────────────────────────────────────────────────────────────┘
```

**Rules (prescriptive):**

1. **Position**: directly under the summary strip, above the
   matrix/tree/wide region — the `.mon-card-resume` row family
   (`$text-muted` Secondary role, row tokens, width auto). The dispatch
   block is part of the card content builder (the ONE shared
   `_card_content` seam) so in-place updates keep the ListItem/cursor
   identity (the f0x law).
2. **Dispatch line** (`MON_DISPATCH_LINE`): `调度 {status} · 完成
   {done}/{total} · 队列 {queue}` / `dispatch {status} · {done}/{total}
   done · queue {queue}`. Fields map 1:1 to the frozen schema v2:
   `status` ∈ running/done/incomplete rendered VERBATIM (data, never
   translated — the unrecognized-status passthrough rule), `done` =
   counts.completed, `total` = counts.total, `queue` = queue_depth.
   Unrecognized status values render the raw string (honest passthrough).
3. **Worker rows**: one per `workers[]` entry, in array order. Busy
   (`in_flight` non-null) → `MON_DISPATCH_WORKER_BUSY`: `worker {i} ·
   GPU {gpu} · ⏵ {model} × {task} × seed_{seed}` (glyph-first, data-
   forward, identical in both languages; `fraction` non-null appends `
   × frac_{fraction}`). Idle (`in_flight` null) →
   `MON_DISPATCH_WORKER_IDLE`: `worker {i} · GPU {gpu} · ◌ 空闲` / `… · ◌
   idle`. The ⏵/◌ glyphs reuse the running/queued vocabulary — no new
   glyph.
4. **Stale marking** (D16-08): when the state file's mtime is older than
   **60 seconds** (pinned, documented-tunable module constant — the
   `STALE_GRACE_SECONDS = 600` precedent), the block renders the
   `MON_DISPATCH_STALE` warning row (⚠ glyph, `$warning` channel) ABOVE
   the dispatch line, and the rows still render (last-known-good — the
   tolerant-reader retention rule); the marker clears on the next fresh
   read. A live dispatcher writes at every transition, so 60s stale on a
   `running` status honestly signals a stalled orchestrator.
5. **Absent file** → no block (not even an empty placeholder); damaged
   JSON → the reader degrades to None → no block (never a crash — the
   tolerant-read discipline). The card's scanner-derived surfaces are
   unaffected.
6. **Snapshot-invariant honesty check (recommended)**: the reader may
   assert `completed + failed + skipped + queue_depth + active_workers ==
   total` (the schema's documented invariant); a mismatch renders the
   stale/malformed ⚠ marker row instead of a silently inconsistent set —
   never a client-side reconciliation.
7. **Cadence**: the dispatch_state read rides the EXISTING 2s frontier
   worker pass (one additional service read per live root inside the
   same exclusive `mon-frontier` group — no new timer, no new worker
   group); the rendered block is content-signature gated like the rest
   of the card.
8. **Where else dispatch data appears**: nowhere else this phase. The
   right pane, [w] wide table, History rows, and the drill modal are
   UNCHANGED (surgical scope; D16-13's golden delta stays minimal).

## Data Contracts (service tiers — textual-free, D16-07)

### `tui/services/gpu_probe.py` (TUI-01, D16-01..D16-04)

```python
@dataclass(frozen=True)
class GpuRow:
    index: int              # CSV column 1
    utilization_pct: int    # column 2 (utilization.gpu)
    memory_used_mib: int    # column 3 (memory.used)
    memory_total_mib: int   # column 4 (memory.total)
    temperature_c: int      # column 5 (temperature.gpu)
```

- Probe argv (verified live on the validation box, 2026-10-21):
  `nvidia-smi --query-gpu=index,utilization.gpu,memory.used,memory.total,temperature.gpu
  --format=csv,noheader,nounits` → lines `0, 0, 2, 32607, 29`. Units are
  FIXED by the query (%, MiB, °C) — the dataclass names carry them; no
  runtime unit parsing, no fabrication.
- Failure = missing binary, non-zero exit, timeout, unparseable line →
  the absent/degraded result (a `rows=None`-shaped outcome — never an
  exception, never partial rows from a partial parse; a malformed LINE
  degrades the whole probe, the deps-tolerance per-package rule).
