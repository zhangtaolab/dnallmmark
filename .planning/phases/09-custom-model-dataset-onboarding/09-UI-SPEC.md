# Phase 9 — UI Design Contract

> Visual and interaction contract for the custom-onboarding surfaces of the DNALLM-Mark
> terminal console (Textual TUI). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Evolution contract.** This spec **inherits the approved Phase 8 contract**
> (`.planning/phases/08-tui-foundation-env-check-selection/08-UI-SPEC.md`, approved
> 2026-10-11) and adds only what Phase 9 introduces. Inherited verbatim, restated here only
> by reference: the **Terminal Contract** (80×24 minimum grid + min-size guard, 120×40
> design grid, UTF-8, NO_COLOR degradation, keyboard-first/mouse-additive, wide-char
> discipline), the **Spacing Scale** (cell tokens md 4 / lg 8 / xl 12 + the 1/2-cell
> exceptions), **Typography** (1 size, exactly 2 weights, hierarchy = weight+color+position;
> no italics/underline/blink), the **I18N Contract** (`tui/strings.py` single home,
> Chinese-primary, English technical terms verbatim), the **glyph+color redundancy rule**,
> and the glyph vocabulary (✓ ✗ ⚠ ◆ ◌ ⠋ …). Where this spec amends an inherited list
> (color accent reservations, screen layouts, keyboard map, copy table), the amendment is
> explicit and additive. Phase mode is `--auto` (09-CONTEXT smart-discuss already ratified
> D-01..D-16): every remaining would-be design question is recorded in
> `## Auto-Selected Defaults` as a recommendation the maintainer may override at plan review.
>
> **Terminal, not web.** As in Phase 8: no px, no fonts, no hex outside tokens; all
> dimensions are terminal cells; the web leaderboard's CSS is not the design system here.

## Navigation Shell (NEW — D-13..D-16, RATIFIED; do not re-open)

Two 1-row chrome bars on the **base screens** (环境检查, 选择, 关于). Base screens replace
the Textual `Header` + `Footer` widgets with these bars — row-neutral (1+1 replaces 1+1),
so the **content budget is unchanged**; both bars count against the 80×24 minimum grid
(D-16). The 矩阵总览 auxiliary view and all modals render **without** the bars and without
digit navigation (existing behavior unchanged for the matrix; ModalScreen blocking for the
modals). Below 80×24 the min-size guard takes over full-screen and hides everything —
existing behavior, byte-identical (D-16).

### Top menu bar (D-13, 1 row)

```text
 ◆ 1 环境检查   2 模型·数据集   3 数据管理 (未开放)   4 运行配置 (未开放)   5 任务监控 (未开放)   6 关于
```

- Slot labels are the **ratified verbatim resource-noun names**: `环境检查` · `模型·数据集`
  · `数据管理` · `运行配置` · `任务监控` · `关于` — never renamed, never re-translated.
- **Active slot**: `◆` prefix + bold + `$accent` (glyph+color+weight triple channel;
  `◆` is reused from the marked-family vocabulary — the shell "marks" the active screen;
  fully legible under NO_COLOR).
- **Inactive open slots** (1, 2, 6): regular weight, `$text-primary`.
- **Placeholder slots** (3, 4, 5): dim (`$text-muted`) + a `未开放` suffix. Pressing their
  digits fires a toast naming the delivering phase (Copywriting table) — never silent,
  never a dead key.
- **Digits 1–6 are direct access** keys, declared **per base screen** (not app-level) so
  the matrix view and modals never intercept them, and an Input's focused editor always
  consumes digit keystrokes first (typing `1` in a wizard field types `1`, never switches
  screens — see Interaction semantics #1).

### Bottom submenu bar (D-15, 1 row)

```text
 [w]接入 [e]停用 [space]标记 [/]过滤 [m]数据集 [p]预设 [x]模板 [v]矩阵 …   [?]帮助 [q]退出
```

- **Left segment**: the active screen's command keycaps, migrated from the Phase 8 Footer
  — same data source (the per-screen `BINDINGS` declarations read via the existing
  `_binding_row` helper, `tui/app.py`), same rendering treatment (key char `$accent`,
  label `$text-muted`, `[k]标签` format). The migration is presentational; binding
  declarations stay per-screen.
- **Right segment**: constant `[?]帮助 [q]退出` — the app-level bindings, always visible.
- **Overflow policy** (the selection screen now carries 9 left-segment keycaps — over the
  80-col budget in full): the left segment renders in binding-declaration order and clips
  at the available width with a trailing `…`; screens declare bindings in importance
  order (primary actions first) so clipping drops the least-primary keycaps first. The
  `?` help modal always lists the complete map (the discoverability backstop, inherited).
  At the 120×40 design grid the full map renders.

### Footer → bottom-bar migration table (what moves where)

| Phase 8 surface | Phase 9 disposition |
|-----------------|---------------------|
| env screen Footer `[r] 重检` `[enter] 详情` | left segment, unchanged |
| env screen Footer `[s] 选择` | **REMOVED** — superseded by menu slot `2` (one navigation path; no redundant alias) |
| selection screen Footer (`space m p x s v /`) | left segment, unchanged labels |

| 矩阵总览 `←/→ 横向滚动 · esc 返回` hint line | kept as-is; matrix renders no menu bars |

```text
 ◆ 1 环境检查   2 模型·数据集   3 数据管理 (未开放)   4 运行配置 (未开放)   5 任务监控 (未开放)   6 关于
 ──────────────────────────────────────────────────────────────────────────────────────
 关于 DNALLM-Mark
   软件版本     0.7.1 (v1.2 TUI任务, git a8dba7c)
```

- **Read-only**: the only bindings are the nav digits, `?`, `q`. No refresh, no action
  keys — D-13 calls it 只读信息屏.
- Rows are the five D-13 items (`软件版本 / 数据版本 / 里程碑阶段 / 依赖版本 / 仓库地址`)

  (values are service-provided; derivations in Auto-Selected Defaults #13).

  renders `未安装` (dim), never an error; the screen never fails to compose (the partial

## Existing-Surface Amendments (选择屏, CUST-06)

The selection screen gains the custom-entry presentation; everything else is inherited

### Custom badge (D-10, dual channel)

```text
  标  模型                              类型   物种      规模(M)
  ✓   plant-dnamamba-6mer               MLM    plants    396
      ◇ my-custom-dna-lm                MLM    plants    88
  ✓   ◇ my-other-lm（已停用）            CLM    human     310
```

- Custom entries render a **`◇` prefix on the key column cell** in **both** tables — bold
  + `$accent`; official rows render no prefix. `◇` (white diamond) is the hollow kin of
  the `◆` mark glyph: same geometric family, visually distinct, single-cell, widely
  covered (the A2 glyph-coverage assumption extends to it), and NO_COLOR-legible (glyph +
  bold carry the meaning).
- **Disabled custom entries stay visible** for management: badge rendered dim + a
  `（已停用）` suffix on the key cell. They are excluded from the overlay-merged pipeline
  view (D-09 loader-level skip) but retained in the table via a service-side read of the
  user-owned custom file — you cannot re-enable what you cannot see.
- **Marking a disabled custom row is blocked** with a warning toast (fool-proofing: a mark
  the sweep can never see is a silent failure at launch). Presets that reference disabled
  custom keys follow the Phase 8 unknown-key loud-skip behavior.

### Count line (D-10)

- The title-bar status line keeps its Phase 8 shape with overlay-merged totals:
  `已标记: 模型 {n}/{models_total} · 数据集 {m}/{tasks_total}`.
- When at least one custom entry is landed, a second dim segment appends:
  `官方 {official_models}/{official_datasets} · 自定义 {custom_models}/{custom_datasets}`
  — counting **landed custom entries (enabled and disabled)**: what you see in the table
  is what you count; disabled ones are visibly marked, and the sweep-visible (enabled)
  count is derivable from the markers. Zero custom entries → segment omitted (the
  official-only state is the Phase 8 look, unchanged).

### Enable/disable + wizard entry (D-09/D-11/D-12/D-14)

| Key | Context | Action |
|-----|---------|--------|
| `w` | 选择屏 (either table) | open the **new-entry wizard for the active table's type** (models table → model wizard; datasets table → dataset wizard). Cursor on a custom row additionally prefills fields from that entry as a re-record aid (D-12: 编辑 = 删除 + 重录; the key field still must change — collision validation enforces). Cursor elsewhere → blank form. (Prefill is an auto-default, #15.) |
| `e` | 选择屏, cursor on a **custom** row | toggle 启用/停用 (flips `enabled` in the user-owned custom registry; toast feedback). Reversible → no confirm modal. |
| `e` | 选择屏, cursor on an **official** row | no-op with toast `官方条目不可停用` — never silent. |

## The Wizard (CUST-01/02/03/04 — NEW modal family, D-01..D-08)

One ModalScreen family, two type-aware instances. Chrome shared by both:

- **Step indicator**: the modal border title carries `新增{类型} — 步骤 {n}/{total} · {步骤名}`
  — the current step number renders `$accent` + bold. No separate progress-glyph row.
- **Modal width**: `min(100, width−4)` cells — **wider than the Phase 8 modal token (60)**
  by explicit amendment: the UAT width lesson (68-char registry keys, long absolute paths)
  demands realistic-content fit. Inputs additionally scroll their own buffer (Textual
  Input behavior, inherited), and every full-value surface (validation report, gauntlet
  detail, row detail) wraps and never elides (RichLog, inherited).
- **Keys**: `enter` = 下一步 (on the last step: submit → validation) · `esc` = cancel ·
  `b` = 上一步 (values preserved — auto-default #4) · `tab` cycles fields within the step
  (Textual focus order). Step-1-only affordances: `f` = 从文件导入, `o` = 导出自定义注册表
  (D-11; both are auto-default placement #7).
- **esc-cancel is confirmed when any value is entered** (ConfirmModal, the destructive
  list): losing typed wizard data is the same annoying-to-lose class as 清除全部标记.
- **Value preservation is contract**: dismissing the validation report or a failed
  gauntlet returns INTO the wizard at the same step with every entered value intact.
  Only an explicit esc-confirm, a successful land, or a used undo clears the form.

### 新增模型 — 4 steps (CUST-01)

| Step | 步骤名 | Fields (control) |
|------|--------|------------------|
| 1 | 基本信息 | 键名 (Input — the registry key, required) · 本地路径 Model_path (Input + **live existence check**) · 规模 size (M) (Input, numeric) · 物种 species (SelectionList over the registry's observed values, sorted; 不填 allowed) |
| 2 | 架构与分词 | 类型 type (SelectionList: MLM / CLM / DL) · architecture (Input, optional free text) · tokenizer (SelectionList over observed values: BPE / singlebase / one-hot / 6-mer / overlapped 6-mer — canonical field `Tokenizer`, the casing-twin discipline) · context_len (bp) (Input, numeric, optional) |
| 3 | 来源链接 | huggingface URL (Input, optional) · modelscope URL (Input, optional) · series (Input, optional) |
| 4 | quirk 勾选 | Checkbox set (D-02): `不使用 safetensors` · `仅支持 fp32` · `需要特殊头 (head)` — all optional, unchecked default. `enter` here submits. |

### 新增数据集 — 4 steps (CUST-02)

| Step | 步骤名 | Fields (control) |
|------|--------|------------------|
| 1 | 基本信息 | 键名 (Input, required) · 数据集路径 Dataset_path (Input + live existence check) · Category (SelectionList: Animals / Plants / Microbe / Multiple) |
| 2 | 数据文件 | train / dev / test 文件名 (3 Inputs + live existence check; parseability is the collect-all pass's job) · 标签列 label column (Input, validated against the CSV header at validation) · 标签数 labels (Input, numeric) · 序列长度 length (Input, numeric, optional) |
| 3 | 任务与指标 | Task_type 任务类型 (SelectionList: binary / multiclass / regression / multilabel — **stored under the registry's field name `type`**, see #11) · 主指标 metric (SelectionList from the metric registry — `SUITE_CANONICAL` in `script/export_runs.py`, the IN-03 single authority; English verbatim) |
| 4 | 溯源信息 | citation (Input, optional) · source URL (Input, optional) · license (Input, optional) · preprocessing 备注 (Input, optional). `enter` here submits. |

Landed-entry field mapping (registry-row compatibility) is service-side and plan-owned;
the wizard's field labels follow the CUST-01/02 requirement wording.

### Type-aware controls (D-03)

- **Enums → SelectionList**, single-pick enforced in the screen (a new pick clears the
  previous one) — SelectionList is multi-toggle by default; the wizard's enum fields are
  exactly-one (or zero-when-optional) and the screen enforces it so validation never has
  to apologize for widget defaults.
- **Paths → Input + live existence check**: a dim glyph line under the field flips on
  change — `✓ 路径存在` (`$success`+glyph) / `✗ 路径不存在（仍可继续，提交时统一校验）`
  (`$error`+glyph, advisory). Advisory only — the authoritative check is the collect-all
  pass (the operator may be onboarding a not-yet-downloaded path; fool-proofing does not
  become blocking).
- **Numerics → Input** with an inline dim `✗ 需为数字` hint on non-numeric content
  (advisory), authoritative in the collect-all pass.

### Validation report (CUST-03 — collect-all, D-05/D-08)

On submit (`enter` at step 4) the wizard switches to the report view — the established
`SEL_TEMPLATE_PROBLEMS` shape, type-aware:

```text
 ┌─ 新增模型 — 校验 ──────────────────────────────────────────────┐
 │ ✗ 校验失败 — 共 3 处问题：                                     │
 │  1. 键名: 与官方条目冲突 (plant-dnabert-6mer)                   │
 │  2. 本地路径: 路径不存在 (models/my-lm)                          │
 │  3. 规模(M): 需为数字 (abc)                                    │
 │                                               [esc] 返回修改    │
 └────────────────────────────────────────────────────────────────┘
```

- **One pass, every problem, numbered, in field-definition (pointer) order** — required /
  type / enum / key-collision (official AND existing custom) / path existence / split
  parseability / row count > 0 / label-column validity / metric-in-registry. Never one
  error at a time (the `_validate_filters` discipline, fourth instance).
- **Nothing is applied on failure.** `esc` (or `enter`) returns to the wizard at the same
  step, values intact.
- On pass the flow proceeds **automatically** to the gauntlet.

### Gauntlet panel (CUST-04 — D-06/D-07/D-08)

```text
 ┌─ 接入 gauntlet — my-custom-dna-lm ─────────────────────────────┐
 │ ✓ dry-run 预检        6 cell(s) 计划成功                        │
 │ ⠋ audit 对账          行数 / 非ACGT / 子集存活 …                 │
 │                                                       [esc] 返回 │
 └────────────────────────────────────────────────────────────────┘
```

- **Type-aware item rows**: model entry → `dry-run 预检` (subprocess `run_sweep.py
  --dry-run` over the staged overlay, D-06); dataset entry → `dry-run 预检` **and**
  `audit 对账` (行数 / 非 ACGT / 子集存活, D-07). Each row is one gauntlet item.
- **Async inline fill** (the env-panel pattern): rows start `◌ 待检`, flip `⠋ …运行中`
  then `✓`/`✗` as the thread-worker subprocess posts results — the console never freezes,
  no full-screen spinner. `enter` on a row drills down to the subprocess's own output
  lines **verbatim** in a RichLog (data, not copy — the D-02 verbatim discipline).
- **All ✓ → the write happens** (D-08: gauntlet 全过才落盘): a final row
  `✓ 已落盘: {key} → {path}` appears, the success toast fires, and the result panel
  carries the **session-undo affordance**: `[u] 会话内撤销` — `u` performs the
  entry-level rollback (removes the just-landed entry), toasts `✓ 已撤销 {key}`, and the
  affordance is gone once the panel closes (session-scoped by design).
- **Any ✗ → the entry never lands** (zero half-written state; official registries
  provably untouched): a prominent failure banner
  `✗ gauntlet 未通过 — {key} 未落盘（官方注册表零触碰）` (error color + glyph), drill-down
  detail available, `[esc] 返回向导` with values preserved — fix and retry.

### File import / export (D-11 — entry points in the wizard)

- **导入 (`f` on step 1)**: path Input (the `PathInputModal` idiom) → collect-all
  validation of the file (schema + every key collision against official AND existing
  custom, listed once, numbered — the report surface above) → nothing merged on any
  problem; on a clean pass the entries merge and the gauntlet runs **per imported entry,
  sequentially, in the same panel** (rows grouped per entry) — a failing entry reverts at
  entry level while the others land (D-08 entry-level rollback; #6).
- **导出 (`o` on step 1)**: path Input → copy the active type's user-owned custom
  registry file verbatim to the operator path (the file IS the shareable unit) → toast.
  No landed custom entries → toast `尚无自定义条目可导出` (the empty state).

## Keyboard & Interaction Contract (additions to the Phase 8 map)

Phase 8 bindings carry over except where the migration table disposes them (`s` on env
removed; Header/Footer retired on base screens). New:

| Key | Surface | Action |
|-----|---------|--------|
| `1`–`6` | base screens only | direct menu access (slot 6 = 关于). Placeholders 3/4/5 → toast naming the delivering phase. Never fires while an Input is focused, on the matrix view, or inside modals. |
| `w` | 选择屏 | open the new-entry wizard for the active table's type (D-14) |
| `e` | 选择屏 | 启用/停用 toggle on custom rows; official rows no-op with toast |
| `f` | wizard step 1 | 从文件导入 (D-11) |
| `o` | wizard step 1 | 导出自定义注册表 (D-11) |
| `enter` | wizard | 下一步; last step = submit (validation → gauntlet); gauntlet row = drill-down |
| `b` | wizard | 上一步 (values preserved — auto-default #4) |
| `u` | gauntlet result panel | 会话内撤销 the just-landed entry (session-scoped) |
| `esc` | wizard / report / gauntlet | cancel-with-confirm (if values entered) / return to wizard (values intact) — never quits the app (inherited) |

**Interaction semantics that are contract, not implementation detail:**

1. **Digit navigation scope** — digits are declared per base screen (or an equivalent
   mechanism that yields exactly this behavior); an Input's focused editor consumes
   printable keys first, the matrix view and ModalScreens never see digit navigation.
   TUI navigation never orphans the shared mark sets (the `build_selection_screen`
   live-instance discipline continues — zero-arg SCREENS slots remain forbidden for the
   selection screen).
2. **One navigation path per target** — menu slot `2` is *the* way to 选择; the env `s`
   alias is retired. The `?` help modal remains the complete live key map (its rows come
   from the same BINDINGS declarations — automatic).
3. **The gauntlet is the only write path** — no UI path writes the custom registries
   except an all-✓ gauntlet completion (and the undo's rollback, and the `e` toggle's
   `enabled` flip). Official registry files are never written by any flow (binding
   constraint 11); the failure copy says so.
4. **Value preservation** — validation-report and failed-gauntlet dismissals return into
   the wizard with all values intact; only esc-confirm, land, or a used undo clears.
5. **Disabled-entry semantics** — disabled custom rows stay visible (management read),
   cannot be marked (warning toast), are excluded from the overlay the pipeline loads
   (D-09), and count in the `自定义 N/M` segment (visible = counted).
6. **Single-pick SelectionLists** — enum fields clear the previous pick on a new one.
7. **Subprocess discipline** — dry-run/audit run in a thread worker (`@work(thread=True)`
   posting per-item messages, the 08-06 pattern); gauntlet results carry the run-id
   message-tag discipline (WR-02) so async results cannot cross entries.
