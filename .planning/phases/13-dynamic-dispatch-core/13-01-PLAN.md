`pipeline/run_sweep_shard.py` routes to a new sibling engine (`pipeline/dispatch_core.py`)
that re-parses the sweep-flag remainder through run_sweep's own parser, enumerates the

routing), `tests/test_dispatch_core.py` (new suite).

<decisions_and_assumptions>
Recording the research planner-gate items as explicit plan-level decisions (13-RESEARCH
Assumptions A2/A3/A5 + open questions; CONTEXT `<decisions>` is the locked authority):

- **A2 (locked by plan): failed cells are NOT requeued within a live dispatch run.** A
  failed cell finalizes its claim to state `failed` and counts in dispatch_state.json;
  re-run is Phase 14 (MGPU-04). In-run requeue would double work and muddy the
  exactly-once proof (research anti-pattern).
- **A3 (locked by plan): Phase 13 dispatch roots carry child artifacts + the ledger +
  `dispatch_state.json` but NOT `sweep_manifest.json`/`run_record.json`** (Shape 1
  workers bypass run_matrix; exporters see a manifest-less root and the scanner falls
  back to churn semantics — the documented Phase 14/15 handoff). The dry-run plan
  artifact (Plan 13-02) is the only manifest-shaped output.
- **A5 (locked by plan): stale-lock reclaim = pid-liveness.** The lock JSON records the
  dispatcher pid + run_id + started timestamp. On lock-exists: `os.kill(pid, 0)` —
  succeeds → loud collect-all refusal naming pid + run_id; `ProcessLookupError` →
  provably dead → reclaim by overwrite. No lease, no timeout (CONTEXT ruling). The
  orphan-children caveat (a SIGKILLed dispatcher leaves `start_new_session` children
  running; kill orphans before relaunch — the claim JSON's child pid makes them
  findable) is documented in the dispatch_core module docstring, mirroring the v1.2
  killpg runbook obligation.
- **A6 (locked by plan): `--mode dispatch` + `--merge` on one command line is refused**
  with a named problem at routing time (main(), before either mode runs).
- **Discretion — module split:** the engine lives in a NEW sibling
  `pipeline/dispatch_core.py` (compose-as-sibling-module pattern, flops_counter/
  registry_loader precedent); `run_sweep_shard.py` gains only the flag, routing, and
  (Plan 13-02) the merge-evidence check. run_sweep.py and run_finetune.py are read-only
  import targets.
- **Discretion — claim filename (frozen by tests):** readable + injective —
  percent-encode each field via urllib.parse.quote with safe set empty, join the model /
  task / seed{n} [/ frac{f}] fields with the token `--`, append `-` + the first 12 hex
  chars of sha256 over the canonical JSON of the cell tuple, extension `.json`. The full
  tuple is ALSO stored inside the claim JSON. The digest suffix guarantees injectivity
  regardless of quoting edge cases (research Pitfall 5 — `+` aliases, `__` task keys,
  float fractions, `--`-containing names).
- **Discretion — queue mechanics:** one in-memory pending list guarded by a
  threading.Lock; one thread per `--workers` entry, permanently bound to gpus[i];
  `Popen.wait()` releases the GIL (research Open Question 4 recommendation). Tests use
  PER-CELL scripted fake spawners (research Pitfall 7 — index-scripted codes are flaky
  under multi-worker interleaving).
- **Locked output-root precedence in dispatch mode:** the shard parser's `--output-root`
  (default `./finetuned`, resolved absolute) is the root; `directories.json`'s
  output_root key does NOT redirect the orchestrator (identical to static mode, which
  forwards explicit worker roots). The other four directory keys (cache_dir,
  model_root, dataset_root, log_dir) DO apply the flag > file key > default tier
  exactly as run_sweep.main does (they ride the remainder).
- **--models is required for dispatch launches** (launch-mode requirement, same as
  static): the orchestrator-level WR-07 closure — a full-registry dispatch must be an
  explicit omission on run_sweep's side, not an orchestrator default.
- **Zero-cell semantics:** empty ENUMERATED matrix (filters intersect to nothing, empty
  registry) → refuse by name; empty PENDING set on relaunch (everything skipped) →
  explicit nothing-to-do verdict, exit 0.
- **Flagged assumption (unresolved edge, unclassified row from the coverage probe,
  MGPU-02):** the ledger protocol's behavior when a relaunch happens while ORPHAN
  children of a SIGKILLed dispatcher are still running is DOCUMENTED (kill orphans
  first — module docstring + lock-refusal wording) rather than protocol-gated; the
  tested protocol covers child death + normal relaunch (SC2) and dead-dispatcher lock
  reclaim (unit-pinned).
</decisions_and_assumptions>
